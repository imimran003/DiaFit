# Diafit bug fixes and rebuild — 2026-10-02

The current source was resumed from `055487f`, with two local commits ahead of
`origin/main`. The working tree was clean before this pass. Historical findings
in the July audit are not a current inventory of unresolved defects.

## Fixed in this pass

- A saved alias such as `milk tea` could match a substring of a compound meal
  and return early with only that food. Whole-input saved-food shortcuts now
  require an exact normalized alias and cannot override fresh quantities or
  multiple parsed components. Component-level memory matching is also exact,
  so saved sweetened coffee cannot replace an explicitly named black coffee.
- A schema-valid AI response with no `unresolvedItems` could silently omit a
  locally unknown food. Unaccounted-for words now remain in the review as a
  clarification question. Provider `originalText` spans can account for words
  the local catalog does not recognize. Photo instructions are excluded from
  this text accounting, preserving the existing photo routing guard.
- Concurrent nutrition lookups returned foods in completion order. Results
  now retain input order, tested with deliberately delayed lookups.
- Correcting a photo count from three rotis to two could retain the weight of
  three. Count reconciliation now scales the estimated total mass too.
- Backend photo deduplication was also applied to text, collapsing explicitly
  different preparations into one item. Text keeps separate food spans and
  preparations; identical duplicate rows are still rejected. Both live-provider
  adapters are covered with injected HTTP responses.
